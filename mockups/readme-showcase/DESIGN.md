# README showcase directions

- **Goal:** Compare two ways of presenting a non-empty Pi Chat README showcase, with rich chat/tool output as the lead image and project/session navigation, command discovery, and one light-mode example as supporting images.
- **Scope:** A visual composition study only. This is not a production app redesign, final screenshot export, or approval to replace README assets.
- **Revision:** 6
- **Review status:** Approved — Product first only

## Directions

1. **Product first** (`?layout=product`): restrained GitHub README composition, clean product frame, one large rich-chat hero, and three supporting feature images.
2. **Editorial collage** (`?layout=editorial`): same content and image roles with subtle lilac atmosphere, framed hero, and more deliberate editorial card layout.

Use the two buttons above the README preview to switch directions. The selection is also addressable via the `layout` query parameter.

## Agreed content priorities

- Lead with a populated, readable chat showing a useful assistant answer and expanded tool output.
- Make project and session navigation visible.
- Show the command panel with native and extension command examples.
- Include one light-mode image to make theme support apparent.
- Avoid a large empty welcome screen or a row of interchangeable transcript screenshots.
- Omit the introductory Pi Chat title, tagline, and installation section; begin directly with the workspace showcase.
- Use a single bold “Workspace” heading, without a kicker or tagline.
- Omit the introductory description beside the workspace heading. Supporting images 2–4 retain only their names, without subtitles, indices, or theme badges.

- Supporting captions use “Projects & sessions”, “Commands Panel”, and “Light mode”.
- Omit the numbered hero caption “01 — A real conversation, at a glance”; retain its feature summary.
- Omit the simulated repository header and README footer; retain the external review controls for switching directions.

## Fake or omitted behavior

- All interface content and project/session names are fictional, local static markup. No backend, credentials, Pi runtime, real screenshot, or product interaction is involved.
- The project/session panel, command menu, and tool output are illustrative representations, not pixel-accurate captures of the current application.
- Use the approved Product first composition as the reference for real UI captures. Do not present the fictional interface as actual product screenshots. Final capture fidelity and README integration remain to be implemented.
