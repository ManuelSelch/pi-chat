# Diff viewer
- Revision: 14. Status: approved. User explicitly approved the full-width narrow view, earlier breakpoint, simplified header and Branch default for implementation.
- Goal: simple read-only local Git changes viewer, packaged as an isolated plugin.
- User direction: general optional side panel on the right, usable in parallel with chat; no specialized Changes button, modal, backdrop or focus trap.
- Layout: chat and composer on the left; general side panel on the right (46% of desktop width). Plugin-contributed Changes tab places a slim file-navigation column between transcript and continuous diff stream, with branch/base context, refresh and totals above/below. Compact 28px single-line file rows show icon, filename and status; full paths remain in accessible names and hover titles, without directory sublines or duplicate counts. Header toggle has compact right padding. Panel shell owns tabs and close.
- Entry: neutral right-sidebar icon in the header toggles the general panel; closing restores full-width chat. Keep base choice when toggled; this mockup resets scroll/file highlight on reopening. Changes is currently the only contributed tab; no placeholder features.
- Data: staged and unstaged changes plus untracked files compared with HEAD, the merge-base with a selected local/remote-tracking branch, or a selected recent commit. Working tree is always the comparison target; no session-only filtering. List branches rather than claim automatic true-parent detection.
- Interactions: scroll through every file diff without selecting files; file-list clicks jump within the stream and retain the clicked highlight even when scrolling is clamped or unnecessary; subsequent manual scrolling resumes visible-file tracking. Per-file horizontal scrolling and sticky file headings. Unified diffs only; no split mode. A mode selector offers Branch, Uncommitted and Commit. Uncommitted requires no further selection. Branch reveals a searchable local/remote branch picker; Commit reveals a picker searchable by message. Until a branch/commit is chosen, show a selection prompt instead of unrelated patches. Commit options display message subjects only; hashes remain internal selection identities; selecting an option applies immediately. No manually entered commit hash. No visible Base label or working-tree suffix; keep an accessible comparison-base name. Close/reopen and simulated refresh; chat composer remains usable and appends preview-only messages.
- Below 1048px (approximating the current 760px available-space threshold with the 288px projects sidebar), Changes replaces chat and composer in a full-width, viewport-height view; closing it restores chat and its draft. Chat stays mounted to preserve scroll position. The file column narrows with the viewport; code scrolls horizontally. No overlay.
- States: default populated; query parameters `?state=empty`, `?state=error`, `?state=not-git`, `?state=loading`. Select added/deleted/binary files in the list.
- Fake data only; current branch is feature/diff-viewer. Branches and commit messages are fixture options. Changing the base updates local selection but not the sample patches or totals. Refresh/retry only show temporary busy feedback. Chat messages do not call an agent or persist.
- No editing, staging, reverting, commit-history browser, filesystem persistence or real Git requests. No Read-only footer label.
- Production intent: plugin owns contract, Git reads and tab content; Chat explicitly registers and allowlists it and supplies a general side-panel contribution placement, tab composition and toggle rather than a feature-specific button or overlay.
- Existing projects/session navigation remains available in production; the mockup omits it, not a proposal to remove it.
- Default mode is Branch with main selected. The mockup uses fake data; production Commit shows the selected commit’s own patch.
